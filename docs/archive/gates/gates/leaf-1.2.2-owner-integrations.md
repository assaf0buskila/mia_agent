- [x] G6: Sheets writes require an explicit current authenticated-owner request and are idempotent per owner event; retry cannot duplicate an append.
  EVIDENCE: `answer_owner` threads exact `owner_text` into `ToolContext`. Update/append fail closed unless the current authenticated owner message contains both a conservative HE/EN Sheets reference and an explicit mutation verb (`update`/`append`/`add`/`fill`/`enter` or exact Hebrew tokens `עדכן`/`הוסף`/`מלא`/`הכנס`); generic `write`/`כתוב` never authorize mutation. Missing `source_ref` also fails closed. Hebrew topic phrases such as `השיטות`/`שיטה`, collisions such as `מלאי`/`הכנסות`, and read phrasing such as `write me what is in the Sheet`, cannot authorize a write. Before any port call, a SHA-256 key over source event, canonical operation, and canonical args is claimed under `owner_sheets_write`; cell content is never stored in the key/result. Tests prove no verb/no port call, `Sheet address` and unrelated HE/EN false-positive rejection, explicit HE/EN update/append/fill/enter writes, same event single append, different event separate append, no source ref denial, and outside-allowlist fake denial. A retryable adapter error returns an honest tool result and retains the claim so append is not duplicated. 2026-08-28 focused owner-live/Sheets: 20 passed; Ruff and diff check pass.
