## Ranked actionable findings

1. **Correct the owner-agent Sheets contract (`app/graph/owner_agent.py`).** The system prompt says there is no Sheets read tool and describes Sheets as mirror-only, while `owner_tools.py` registers `sheets_read`, `sheets_update`, and `sheets_append`, their capability handlers enforce the owner principal/allowlist, and ADR-042 accepts this exact surface. Add a prompt-contract test so the contradiction cannot return.
2. **Enforce owner identity at the point that mints `Principal.owner` (`app/api/owner.py`).** `telegram.py` and `inbound.py` currently pre-check membership, but the owner function itself accepts arbitrary direct callers. Reject an empty allowlist or a non-member before claims, persistence, graph execution, or port calls; retain the channel checks as defense in depth.
3. **Stop constructing owner adapters on prospect traffic (`app/api/inbound.py`).** Lazy-build the owner-only port bundle only inside the authenticated owner branch. This prevents an unrelated Instagram/WhatsApp/Gmail prospect event from triggering first-use GSC/GA4 discovery and makes the trust split visible.
4. **Make the total owner-agent tool ceiling exact (`app/graph/owner_agent.py`).** Cap execution within each parallel tool-call batch and return a tool result for every refused excess call. Existing ceiling tests cover one call per response and do not reproduce the overshoot.
5. **Unify Telegram notification transport and retry semantics (`app/services/notifications.py`, `app/services/finalization.py`, later coordinated with `app/domain/hot_handoff.py`).** The service sends only to the first owner and permanently retains a claim after a full send failure; hot handoff already fans out and releases on full failure. Implement one accepted-response/fan-out primitive plus workflow-owned idempotency and multi-owner/partial-failure tests.
6. **Remove two test-only legacy paths.** Delete `build_graph(..., knowledge_lookup=...)` in `app/graph/orchestrator.py` and `scan_inactive_website_conversations` in `app/services/finalization.py`; move their useful assertions to ClientGraph, which is the accepted owner of retrieval and inactivity finalization.
7. **Make client authority explicit (`app/agents/client/graph.py`).** Require callers, including the due-scan entry, to pass `Principal.client(...)`; do not let a graph compiler mint its own trust object.
8. **Apply mechanical owner-boundary cleanup (`app/api/owner.py`) and health truth alignment (`app/main.py`).** Remove the unused `calendar_booking` argument, replace duplicated no-due logic with one named set, remove no-op `pass` statements, and expose ADR-042 Sheets readiness without breaking existing monitoring keys.

Optional polish after the ranked work: add signed-malformed-JSON regression tests and local decode handling to the two Meta webhook routes. This is bounded hardening, not a reason to merge the Instagram and WhatsApp parsers.

## Explicit no-change conclusions

- **Do not merge OwnerGraph and ClientGraph.** The two compiled entry points and separate state types are the security and product boundary.
- **Do not add another runtime owner agent, planner, router model, rewrite model, or provider.** The existing single owner loop remains the only production owner agent.
- **Do not move reasoning or policy into `app/channels/telegram.py` or `app/channels/website.py`.** Both adapters are already appropriately thin.
- **Do not move deterministic owner writes/approvals into the model loop.** `process_owner_item` is long because it protects heterogeneous deterministic actions; only local, mechanically verifiable simplification is justified.
- **Do not weaken request-derived Principal propagation.** The recommended changes make principals more explicit; they do not introduce ambient context or let callees choose owner trust.
- **Do not remove or reorder webhook/operation/finalization idempotency.** Improve full-failure claim release with concurrency tests; never replace claims with read-before-write checks.
- **Do not merge Instagram and WhatsApp payload parsers.** They share Meta transport concepts but have different message, voice, story, referral and attribution contracts.
- **Do not change the website route/response/widget contract, Telegram HTML/callback behavior, voice-as-input-only rule, WhatsApp-human-inbox rule, or handoff truth copy in this cleanup.**
- **Do not collapse outer `ClientState` and inner `GraphState` merely to reduce lines.** The current strangler is explicit and tested; inlining requires its own bounded design and verification.
- **No whole assigned file is proven dead.** The REMOVE work is symbol-level only (`knowledge_lookup`, the service inactivity scan, and the unused owner compatibility parameter).

## Audit method and evidence boundary

Four passes were completed:

1. Inventory: exact 23-file/133-definition scan and full-file reads.
2. Expert reread: product, architecture, accepted ADRs, Phase 1.5 contract, graph/channel/trust/idempotency contracts, and direct runtime callers.
3. Defect/duplication hunt: repository-wide symbol/import searches and focused test inspection, including test gaps for Sheets prompt truth, parallel-call ceiling, owner-mint membership, multi-owner finalization, and failed-send retry.
4. Free polish: mechanical candidates separated from behavior/architecture changes; no proposal is justified by file length alone.

This is static audit evidence. No test result is claimed in this leaf because no implementation was authorized and the current dirty tree already contains unrelated in-progress changes. Existing test files are cited as caller/contract evidence, not reported as freshly passing.
